# dasSDL3 0.1.0 — draft release notes

Status: prepared locally; no tag, GitHub release or package-index entry created.
Planned tag: v0.1.0. Project license: MIT.

## Package scope

First daspkg distribution of SDL 3.4.16 bindings for daslang on Windows x64,
MSVC Release, /MD and AVX2. Two mutually exclusive profiles of one package:
core (63 boost modules) and imgui (64, including SDL3 platform/renderer backends).
Both share a single statically linked SDL runtime.

The supported SDK is the reference DLL build of daScript
ebac0ffe46ab30de6c9536f4b0af7a33ede45902. Older SDKs are not supported. Source installation
checks full SDK fingerprints, then builds the module against that SDK.
Binary modules from different SDK builds are not interchangeable.
The metadata minimum 0.6.4 is a coarse package-manager filter, not a guarantee
that every newer SDK is compatible.

## Included

- Root daspkg manifest and consumer-SDK CMake entry; no initialized submodules needed.
- Binary/source staging and core/ImGui consumer examples.
- Pinned SDL source download and ImGui backends from the matching SDK.
- Result/Option, scoped resource helpers and typed checked GPU handles.
- Standalone application release with runtime modules and license notices.
- Portable PowerShell verification kit with file hashes, pixel checks and logs.

## Validation

Native builds, package install/check, all profile imports, source/repository
installation, relocation, GUI pixels and resource cleanup pass. Standalone
checks reject missing native dependencies. Wrong or mixed SDK fingerprints
are rejected.

A user reported successful core/GUI verification on another Windows machine for
an earlier SDK kit. That result does not validate the updated SDK on another
machine. No additional second-machine test has been performed for this revision.

## Limits

This release describes package distribution support, not runtime validation of
every SDL API or GPU/backend. Other operating systems, Web packaging, physical
GPU/input devices and interactive GUI behavior need their respective checks.
Companion SDL libraries, shader DSL, widgets-v2 and live/HTTP are not included
in these package profiles. Their repository implementations remain separate.

Installation needs CMake, Ninja, MSVC and a supported SDK; initial source downloads
need network access. Running standalone demos needs Windows x64 with AVX2 and
the Microsoft VC runtime, but no SDK/Python/LLVM. Building standalone EXEs needs LLVM.

## Install after publication

From a VS x64 developer PowerShell with the supported reference SDK:

~~~powershell
$env:CMAKE_GENERATOR = "Ninja"
$env:DASSDL3_PACKAGE_PROFILE = "core" # or imgui
C:/daslang/bin/daslang.exe C:/daslang/utils/daspkg/main.das -- install github.com/spiiin/dasSDL3@0.1.0 --root C:/my-app
~~~

Keep the profile environment setting for rebuilds. Omitted version/latest follows
main; use @0.1.0 for a tagged release. The tag does not exist yet.
See ../daspkg.md for SDK hashes, source/binary packaging and runnable examples.
