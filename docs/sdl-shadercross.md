# SDL_shadercross

Enable `DASSDL3_WITH_SHADERCROSS=ON`. This independently builds the offline
`shadercross` CLI and optional `sdl3_shadercross` module in the libraries runner.
The option is OFF by default; core SDL users do not acquire shader compiler dependencies.
Require `dassdl3/sdl3_shadercross_boost` for Result/scoped helpers.

## Pins and dependencies

Upstream currently has no release tags. The header says 3.0.0, but the identity is
[commit 1ff05bec573988a98ef9e0260b4da44f512b8367](https://github.com/libsdl-org/SDL_shadercross/tree/1ff05bec573988a98ef9e0260b4da44f512b8367),
not a released SDL_shadercross 3.0.0 package. CMake uses SHA256-verified archives:

- SDL_shadercross: `60aae35ff71bd1d5f85b363e9d077a86bb27dd36333c42685e56c2fd541174d2`.
- Its upstream SPIRV-Cross submodule `1a6169566c73d3da552748fc372fe2bbb856e46e`:
  `0f295b214b164e42a1d21537c8da7b44569806c16220dda9798558edfaacd11e`.
- Official [DXC v1.9.2602 Windows SDK](https://github.com/microsoft/DirectXShaderCompiler/releases/tag/v1.9.2602),
  `dxc_2026_02_20.zip`: `a1e89031421cf3c1fca6627766ab3020ca4f962ac7e2caa7fab2b33a8436151e`.

Windows x64 downloads DXC binaries by default. `DASSDL3_DXC_ROOT` overrides the SDK
root (`inc`, `lib/x64`, `bin/x64`). DXC is not compiled from source: no additional
LLVM source tree or libclang generator SDK is required. DXC itself uses LLVM;
`dxcompiler.dll` and `dxil.dll` remain runtime dependencies of this enabled module
and CLI. CMake copies them beside project executables, with SDK license texts under
`bin/licenses/dxc`. External hosts must package the DLLs themselves.
SDL_shadercross is zlib-licensed; SPIRV-Cross is Apache-2.0; preserve their notices
and the DXC SDK's LLVM/MIT/MS license texts when distributing artifacts.

`DASSDL3_SHADERCROSS_DXC=OFF` disables HLSL-to-SPIRV and DXIL support. SPIRV-Cross
remains available for SPIR-V reflection and MSL/HLSL translation. DXBC requires a
platform FXC runtime; support masks and errors are authoritative. In the no-DXC
profile, HLSL-to-DXBC must skip the default SPIR-V roundtrip using the upstream
`SDL_SHADERCROSS_PROP_HLSL_SKIP_SPIRV_ROUNDTRIP_BOOLEAN` property.
Other operating systems must supply their SDK root or disable DXC; local validation
is Windows x64 only. No WebGPU, browser compiler, GLSL frontend, Metal binary
compiler or shader DSL is added by this integration.

## Offline path

Build `shadercross` to use `build/ninja/bin/shadercross.exe`:

```powershell
.\build\ninja\bin\shadercross.exe .\examples\libraries\shaders\shadercross.frag.hlsl -s HLSL -d SPIRV -t fragment -e main -o fragment.spv
```

Or build `dassdl3_shadercross_example_assets`: normal CMake output rules produce
`bin/assets/libraries/shadercross/fragment.spirv`, `.dxil`, `.msl` and `.json`.
Source/compiler/DXC DLL changes invalidate these files; unchanged builds reuse them.
This is a build rule, not a new renderer cache or runtime pipeline layer. Applications
can ship these outputs and disable the shadercross module in their runtime build.

## Binding and ownership

All **15 raw functions**, **7 structures**, **2 enums** and **6 property strings**
are generated by `tools/generate_shadercross_bindings.py`. Raw pointer/size and
allocation signatures remain unchanged. Version and declaration counts are checked.
**11 native adapters** borrow byte arrays synchronously, copy compiler output,
copy reflection strings/arrays and adapt metadata references. **12 boost helpers**
use the existing Result/SdlError/defer conventions. No panic, catch or custom owner registry.

- Raw compiled buffers, translated text and reflection allocations require `SDL_free`.
  Graphics reflection is one upstream allocation: do not separately free its members.
- Boost compiled byte arrays and translated strings own copies; native allocations
  are released after copying. Reflection returns resource counts and owned input/output
  arrays with copied names. Compute metadata is a value.
- `with_shadercross` matches Init/Quit. Use one application-owned session, not nested
  scopes. Init/Quit must run on one thread; no reference counting is implied.
- Factories `compile_graphics_shader_spirv` / `compile_compute_pipeline_spirv` return
  ordinary native SDL GPU pointers. Release them with `SDL_ReleaseGPUShader` /
  `SDL_ReleaseGPUComputePipeline` before destroying the device. They introduce no
  pipeline planner or combined shader/material owner. The factory's `props` is the
  GPU creation property ID; these conveniences use default SPIR-V transpilation
  properties. Use the raw SPIRV_Info API for separate transpilation properties.
- Raw HLSL `defines` is a borrowed, null-terminated native array. Raw input structs
  retain no storage after synchronous compilation. Pointer construction remains an
  explicit unsafe operation; there is no retained script memory hidden in boost.
- The HLSL info struct supplies source, entrypoint, include directory, stage and props.
  Resource metadata passed to GPU factories must describe the same shader and respect
  SDL's register/set conventions. Reflection does not validate interstage compatibility
  or host uniform layouts.
- Array adapters reject short/misaligned SPIR-V lengths and an invalid magic number,
  and bound copied output to INT_MAX. This is not a full SPIR-V validator.
  Compiler failures are copied immediately from SDL_GetError; a stale SDL error does
  not invalidate success. Init success does not guarantee every target format.

[Example 09](../examples/libraries/09_shadercross.das) compiles a fragment shader
from HLSL, reflects its float2 input, and produces DXIL/MSL. It needs no GPU device.
The braces in embedded HLSL strings are escaped because daScript strings interpolate
braced expressions. The separate `.hlsl` fixture is original project code. Its `.spv` companion was
compiled by the pinned CLI/DXC and is used by the no-DXC profile test; CMake copies
it to `bin/assets/libraries/shadercross-fixture.spv`. It does not overwrite the
incremental asset target's output.

## Validation

`tests/shadercross_native.cpp` executes all 15 raw calls (DXBC conditional on runtime
availability), inspects bytecode/reflection and creates graphics/compute objects on
Vulkan and Direct3D12. The daScript test exercises all 11 adapters, owned reflection
past native free/session shutdown, invalid HLSL/SPIR-V, recovery and GPU factories.
Legacy, CppGenBind and AOT run the same script and example; AOT fallback is disabled.
`DASSDL3_TEST_SHADERCROSS` selects the optional parity suite and its DXC DLL packaging.
The CLI test checks repeated SPIR-V equality, DXIL magic, MSL and JSON output.
Generation/coverage checks accompany the runtime tests. The isolated consumer uses
no LLVM/libclang binding generator and disables every other companion library.
The no-DXC consumer additionally runs `tests/shadercross_no_dxc.das` against the
SPIR-V fixture, checks unsupported compilation errors, and has no dxcompiler/dxil
DLL imports (verified with dumpbin). These tests validate compilation and GPU object
acceptance, not pixel output, Metal
execution, include/define permutations or all possible resource layouts.
