# Аудио: WAV и потоки

Подключение: `require dassdl3/sdl3_audio_boost` (переэкспортирует sdl3_boost).
Слой рассчитан на SDL 3.2.18; пока поддерживается воспроизведение через очередь,
без вызова daScript из фонового аудиопотока. Выбор устройств и запись через
потоки добавлены в [Audio devices](audio-devices.md); запись проверена только на dummy.

Native callbacks, WAV IO, mixing и conversion: [audio-final-api.md](audio-final-api.md).
Callbacks принимают только native C адреса, не daScript blocks.

Полный пример обработки Result и времени жизни: [08_audio.das](../examples/08_audio.das).
Все with_* блоки возвращают Result; успешный выход без значения — `sdl_ok()`.
Ошибки создания, очереди и запросов передаются как Err(SdlError).


Поток закрывается при выходе из блока: для реального воспроизведения нужно
дать ему время обработать очередь (см. полный `examples/08_audio.das`).

## Владение и форматы

- `with_sdl(flags)` позволяет выбрать SDL_INIT_AUDIO или VIDEO | AUDIO.
  Исходная `with_sdl()` по-прежнему включает VIDEO. Используйте одну внешнюю
  SDL-сессию: SDL_Quit глобальный и вложенные независимые сессии не поддержаны.
- `load_wav` возвращает Result с непрозрачным SDL_Wav: он владеет буфером SDL_LoadWAV.
  `destroy_wav` освобождает буфер через SDL_free; `with_wav` делает это также
  при раннем return через defer. Не уничтожайте заимствованный handle внутри блока
  и не сохраняйте его за пределами блока. Уникальное владение типами не обеспечено.
- `wav_spec` возвращает Result с копией SDL_AudioSpec, `wav_size` — Result с размером PCM в байтах.
  `audio_format(spec)` возвращает uint; `audio_spec(format, channels, frequency)`
  создаёт описание формата. Поля channels/freq доступны напрямую, enum format —
  через фабрику и getter. Допустимость описания проверяется SDL при создании потока.
- `with_audio_stream(src, dst)` создаёт поток преобразования без устройства.
  `with_playback(spec)` открывает устройство вывода по умолчанию и связанный
  поток, изначально на паузе. Уничтожение такого потока также закрывает устройство.
  Для запуска нужен resume_audio; pause_audio приостанавливает устройство.
- `queue_wav` требует точного совпадения формата WAV с входом потока (формат
  сэмпла, число каналов, частота). Выходной формат может отличаться. SDL копирует
  данные; после успешной постановки WAV можно уничтожить. Размер свыше INT_MAX
  отклоняется до преобразования в int. Ошибка SDL возвращается как Err(SdlError).
- `put_audio(stream, bytes)` копирует массив uint8 в очередь. Формат байтов обязан
  соответствовать входному формату потока; слой не угадывает кодировку PCM.
  Массив можно изменить/освободить сразу после вызова. Пустой массив — no-op.
- `read_audio(stream, bytes)` заполняет заранее выделенный массив uint8 и
  возвращает Result<int,SdlError> с числом записанных байтов. Массив не увеличивается: обрабатывайте
  только возвращённое количество, хвост не является новыми данными. Пустой
  массив даёт Ok(0). Данные имеют выходной формат потока. Ошибка даёт Err;
  размеры массивов свыше INT_MAX отклоняются без усечения. Адреса не сохраняются.
- `queued_audio` — байты входного формата, ещё находящиеся в очереди;
  `available_audio` — доступные байты выходного формата. Эти числа могут
  различаться при преобразовании/ресэмплинге. `flush_audio` завершает текущую
  порцию, чтобы можно было дочитать хвост ресэмплера. `clear_audio` удаляет очередь.
- Пустая очередь не означает, что устройство физически проиграло последний
  сэмпл. Пример ждёт ещё 100 мс, но это не универсальная гарантия для любого
  устройства. Точного уведомления о завершении воспроизведения пока нет.

Native адаптеры находятся в `src/sdl3_audio.h`, блоки владения используют
`daslib/defer` в `sdl3_audio_boost.das`. Скриптовые функции вызывайте в контексте главного потока
приложения; поток SDL получает только скопированные байты, а не скриптовые блоки.

## Пример и проверки

`examples/08_audio.das` основан на public-domain коде SDL 3.2.18
`examples/audio/03-load-wav/load-wav.c`. Чужая музыкальная запись не используется:
`examples/assets/tone.wav` — собственный тихий сигнал 440 Гц, 0.4 секунды,
mono PCM16 22050 Гц. Генератор: `tools/make_audio_fixture.py`. CMake копирует
файл в `bin/assets`; путь строится относительно SDL_GetBasePath.

```powershell
./build/ninja/bin/dasSDL3_runner.exe examples/08_audio.das
ctest --test-dir build/ninja -R '^sdl3_audio' --output-on-failure
```

CTest устанавливает SDL_AUDIO_DRIVER=dummy для аудиотестов.
Прямой запуск (в том числе с --smoke-test) использует обычное устройство и
проигрывает сигнал один раз. Пример ограничивает ожидание очереди пятью секундами.

Проверки: побайтовое сравнение PCM после уничтожения WAV и изменения массива;
пустые массивы; очистка очереди; преобразование PCM16 mono 22050 в float stereo
44100 с проверкой длины, каналов, конечности и амплитуды; ошибка файла/формата,
обычный и ранний выход, результаты ошибок; callbacks уничтожения SDL properties потока и
счётчик живых WAV; пауза/запуск/закрытие устройства dummy до SDL_Quit.
Тестовые SDLTest* и счётчик WAV отсутствуют при BUILD_TESTING=OFF.

Акустический результат на настоящем устройстве, другие ОС, JIT,
физический микрофон пока не проверен. Native callbacks проверены с dummy и native worker;
script callbacks из аудиопотока не поддерживаются.
